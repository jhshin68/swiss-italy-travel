# DD-005: 지도 — Leaflet + OpenStreetMap

## 상태
✅ 확정

## 맥락 (Context)
여행 앱의 지도 기능을 어떤 라이브러리/서비스로 구현할지 결정.

## 선택지 (Options)

| 선택지 | 장점 | 단점 |
|--------|------|------|
| A. Google Maps | 최고 품질, 상세 POI | API 키 비용, 오프라인 제한적 |
| B. Mapbox | 커스터마이징 우수, 벡터 타일 | 무료 한도 있음, 러닝 커브 |
| **C. Leaflet + OSM** | **완전 무료, 오프라인 타일 캐싱 용이, 경량** | **POI 데이터 품질 구글 대비 약함** |
| D. Kakao Maps | 한국어 친화 | 해외 지도 품질 낮음 |

## 결정 (Decision)
**C안: Leaflet + OpenStreetMap**

이유:
1. 완전 무료 (API 키 비용 없음)
2. 오프라인 타일 캐싱이 자유로움 (라이선스 제약 없음)
3. React-Leaflet 라이브러리 성숙
4. 스위스·이탈리아 OSM 데이터 품질 양호 (유럽은 OSM 강세 지역)
5. 가족 위치 마커, 경로 표시 등 필요한 기능 충분

## 구현 계획

```
라이브러리:
  - react-leaflet (React 바인딩)
  - leaflet (코어)

타일 서버:
  - 온라인: https://tile.openstreetmap.org/{z}/{x}/{y}.png
  - 오프라인: Service Worker로 타일 캐싱 (핵심 지역만)

오프라인 타일 캐싱 범위:
  - 스위스: 취리히, 루체른, 인터라켄, 베른 중심 반경 10km
  - 이탈리아: 밀라노, 베네치아, 피렌체, 로마 중심 반경 10km
  - 줌 레벨: 10~16 (도시 수준~거리 수준)
  - 예상 용량: 50~150MB (사전 다운로드)
```

## 상용화 시 재검토 사항
- Mapbox 전환 검토 (벡터 타일, 더 나은 커스터마이징)
- 자체 타일 서버 운영 vs CDN
- POI 데이터 보강 (Foursquare API 등)
