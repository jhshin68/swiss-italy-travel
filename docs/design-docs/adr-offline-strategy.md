# DD-003: 오프라인 퍼스트 전략

## 상태
✅ 확정

## 맥락 (Context)
해외여행 중 인터넷 연결이 불안정하다. 로밍, Wi-Fi 전환, 산악·터널 구간에서 앱이 무용지물이 되면 안 된다.

## 오프라인 계층 설계

### Tier 1 — 반드시 오프라인 동작 (P0)
| 기능 | 캐싱 전략 | 데이터 크기 (예상) |
|------|-----------|-------------------|
| 일정 열람 (전체 12일) | Service Worker + Cache API | ~500KB |
| 일정 수정 (쓰기) | IndexedDB 로컬 저장 → 온라인 복귀 시 Sync (LWW) | ~100KB |
| 비상 정보 (대사관, 숙소, 보험) | Cache API (앱 설치 시 캐시) | ~50KB |
| 경비 입력 | IndexedDB 로컬 저장 → 온라인 복귀 시 Sync | ~100KB |
| 체크리스트 | IndexedDB | ~30KB |

### Tier 2 — 가능하면 오프라인 (P1)
| 기능 | 캐싱 전략 | 데이터 크기 (예상) |
|------|-----------|-------------------|
| 지도 타일 (핵심 지역) | 사전 다운로드 → Cache API | ~50~200MB |
| 예약 확인서 | PDF 사전 다운로드 | ~10MB |

### Tier 3 — 온라인 전용 (수용 가능)
| 기능 | 사유 |
|------|------|
| 실시간 위치 공유 | GPS 송수신에 네트워크 필요 |
| 환율 실시간 업데이트 | 마지막 캐시 환율 표시 + "업데이트 필요" 표기 |
| 날씨 정보 | 마지막 캐시 날씨 표시 |
| 경비 정산 결과 동기화 | 로컬에서 계산은 가능, 동기화만 온라인 필요 |

## 동기화 전략

```
오프라인에서 생성된 데이터 (경비 입력 등):
1. IndexedDB에 즉시 저장 (timestamp + pending 플래그)
2. 온라인 복귀 감지 (navigator.onLine + online 이벤트)
3. 백그라운드 동기화 (Background Sync API 또는 폴링)
4. 서버와 충돌 시: Last-Write-Wins (가족 4인이라 충돌 확률 극저)
5. 동기화 완료 → pending 플래그 해제 → UI에 ✅ 표시
```

## 결과 (Consequences)
- ✅ 스위스 산 위에서도 일정 확인 가능
- ✅ 기차 터널에서도 경비 입력 가능
- ⚠️ 오프라인 지도 타일 용량이 클 수 있음 → 핵심 지역만 선별
- ⚠️ Background Sync API 브라우저 지원 확인 필요 (Safari 제한적)
  → fallback: 앱 재오픈 시 수동 동기화

## 상용화 시 재검토 사항
- CRDTs(Conflict-free Replicated Data Types) 도입 검토
- 오프라인 지도 타일 최적화 (벡터 타일 전환)
- Service Worker 버전 관리 전략
