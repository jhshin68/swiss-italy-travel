# DD-002: 인증 방식 — 6자리 PIN

## 상태
✅ 확정

## 맥락 (Context)
가족 4인 전용 앱에서 인증 방식을 결정해야 한다. 보안과 편의성의 균형이 핵심.
6자리로 변경한 이유: 4자리 대비 보안성 향상 (오너 결정, 2026-03-29).

## 선택지 (Options)

| 선택지 | 장점 | 단점 |
|--------|------|------|
| A. OAuth (구글/카카오) | 보안 강력, 상용화 즉시 가능 | 구현 복잡, 가족 앱에 과도, 로그인 UX 번거로움 |
| B. 이메일+비밀번호 | 표준적 | 비밀번호 분실 처리, 가족에게 불편 |
| **C. 6자리 PIN + 디바이스 토큰** | **간편, 가족 친화적, 4자리 대비 보안 향상** | **보안 약함 (4인 한정이라 수용 가능)** |
| D. 인증 없음 (URL만 공유) | 가장 간단 | 누구나 접근 가능, 경비 데이터 노출 |

## 결정 (Decision)
**C안: 6자리 PIN + 디바이스 토큰**

- 최초 접속: PIN 입력 → 멤버 선택 → JWT 발급 → httpOnly cookie 저장
- 이후 접속: 자동 로그인 (토큰 유효 시)
- 토큰 만료: 30일 (여행 기간 커버), refresh 없음 (만료 시 PIN 재입력)
- PIN 방식: **가족 공통 1개 (6자리)** — 공통 PIN 통과 후 멤버(진형/지현/동우/유진) 선택 ✅ 확정

## 결과 (Consequences)
- ✅ 가족 누구나 5초 만에 로그인
- ✅ 구현 공수 최소 (1일 이내)
- ✅ 4자리 대비 보안 향상 (경우의 수 4자리 10,000개 → 6자리 1,000,000개)
- ⚠️ Rate limiting 필수 (5회 실패 시 5분 잠금)
- ⚠️ 디바이스 분실 시 → PIN 재입력으로 해결

## 상용화 시 재검토 사항
- OAuth 2.0 (구글/카카오) 추가
- 인증 레이어를 별도 모듈로 분리해두어 교체 용이하도록 설계
- `src/lib/auth/` 디렉토리에 인증 로직 격리
